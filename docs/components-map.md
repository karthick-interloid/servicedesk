# Components Map — ServiceDeskpro

**This document is the allow-list.** Downstream sessions may not create any component that does
not appear here. If a screen appears to need something absent from this table, that is a question
for the maintainer, not licence to build.

## Strategy rules

Strategies are tried **in this order**. A lower strategy may only be chosen when you can state
why every higher one fails — the Notes column carries that statement.

| Strategy          | Meaning                                                                                             |
| ----------------- | --------------------------------------------------------------------------------------------------- |
| `SHADCN-STOCK`    | A stock shadcn primitive, used as-is. Name the primitive and the variant.                           |
| `TEMPLATE-SHARED` | An existing component already in this starter. Name the file.                                       |
| `EXTEND`          | A stock primitive plus an **additive** cva variant. Never edit or remove an existing variant.       |
| `COMPOSE`         | Two or more primitives assembled. List every one.                                                   |
| `UNMAPPABLE`      | Nothing above can work. **This is a question for the maintainer — not permission to build custom.** |

**Starter inventory (38 primitives present):** accordion, alert-dialog, alert, avatar, badge,
breadcrumb, button, calendar, card, carousel, chart, checkbox, collapsible, combobox, command,
context-menu, dialog, drawer, dropdown-menu, hover-card, input-group, input-otp, input, label,
pagination, popover, progress, scroll-area, select, separator, sheet, sidebar, skeleton, sonner,
tabs, textarea, toggle, tooltip.

**Stock shadcn primitives still to add** (`npx shadcn@latest add …`): `table`, `switch`, `form`,
`radio-group`. Rows depending on these are still `SHADCN-STOCK` — the primitive is stock, it
simply is not installed yet.

**Also available:** `src/components/shared/theme-toggle.tsx`, `src/skeletons/home.tsx`,
`src/hooks/use-mobile.ts`, `src/lib/utils.ts` (`cn`), `src/lib/theme.ts`.

## Doc-page section — `/design-system` only

Rows D1–D10 exist because `Design System.dc.html` is a **documentation** page, and the map above
covers the 30 **app** screens. Its component specimens all resolve to rows 39–101; its own
scaffolding did not resolve to anything, which is what these rows fix.

### Boundary — read before using anything below

**Tailwind palette utilities (`bg-slate-950`, `text-slate-300`, `border-slate-800`, …) are
permitted in this section ONLY, and only under the `/design-system` route.** They are forbidden
in the 30 app screens, where **rule 4 stands unchanged**: colour there enters through
`globals.css` tokens only.

Doc chrome deliberately has no tokens. The design's own Special-surfaces block labels slate-950
_"chrome only, not app UI"_, so minting tokens for it would pollute the token contract with
values no product screen is allowed to use. The palette utility is the honest expression of "this
colour is deliberately outside the contract"; a token would be a lie about its status.

**Content cap — stated exception to row 101.** This page caps at **1240px**, not `max-w-[2040px]`.
That is the design's own `max-width` on its container. Row 101's 2040 is the app shell and does
not apply here. Centred, no unbounded stretch, holds to 3840.

**No dark pass.** D1–D10 are specified light-only, matching row 104 and the design's absence of a
dark theme. **If dark ever ships, every one of these ten rows needs a dark pass** — the palette
utilities above are light-surface choices and none of them has a dark counterpart.

## Enforcement

1. A component not in this table does not get built. Raise it instead.
2. `UNMAPPABLE` rows are open questions. They are never a licence to write a custom component.
3. `EXTEND` means **additive only** — add a cva variant, never edit or delete an existing one.
4. No new hex codes in components. Colour enters through `globals.css` tokens only.
5. Status and priority colour always resolves through `lib/badge-tones.ts`, never a literal
   Tailwind palette class.
6. Neutrals are slate-tinted. `gray-*` and `zinc-*` are off-limits.
7. Sibling groups lay out with flex/grid `gap`, not margins.
8. One primary button per view; destructive actions always confirm.
9. Every list screen implements all four states before it ships.

### Strategy changed — recorded, with the reason

1. **Row 39 (Button) — the Notes were wrong, the strategy stands.** The row says _"Variants map 1:1
   to stock `default`/`secondary`/`ghost`/`destructive`. STOCK fails only on sizing."_
   `docs/treatments.md` §8 B1/B2/B4 contradicts that: stock `secondary` is a filled slate chip
   where the design is white + `border-input`; stock `destructive` is `bg-destructive/10
text-destructive` where the design is a solid red fill; stock `default` hovers `/80` where the
   design hovers `/90`. Rendering the page with the stock variants produced a visibly wrong
   Buttons section. EXTEND is still the strategy — four **additive** variant values
   (`primary`/`neutral`/`quiet`/`danger`) were added alongside the stock four, plus the three
   responsive sizes the row already required and a `touch-icon` size for row 41. No stock variant
   was edited. Each carries its reason inline in `ui/button.tsx`.
2. **Row 43 (Badge) — the tone classes live in `lib/badge-tones.ts`, not in `badge.tsx`.** The row
   says the `tone` group goes on `ui/badge.tsx` and that "tone selection must come from
   `lib/badge-tones.ts`". Both are satisfied more literally by exporting `toneClass`/`toneDot` from
   `lib/badge-tones.ts` and consuming them _as_ the cva variant object. Rule 5's single source is
   then structural rather than a convention.
3. **Row 89 (Charts) — kept, not replaced.** A hand-built div bar chart was written first and
   discarded: it would have been a parallel one-off duplicating the mapped primitive. The section
   now uses `ChartContainer` + recharts as the row requires.
4. **D7 (Reference tables) — `table-fixed` is load-bearing.** The design's column widths are grid
   tracks. Stock `ui/table.tsx` has no `table-layout`, so the browser auto-sized from content and
   the widths were ignored entirely. `table-fixed` plus `whitespace-normal` on the cells (stock is
   `whitespace-nowrap`, which overflows a long token into the next track) is what makes the eight
   tables match. Utility classes only; `ui/table.tsx` is untouched.
