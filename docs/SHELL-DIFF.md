## D. Deliberately not built

Shell only, per the brief. None of these are regressions:

- **The search results panel** (`gqPanel`). The design opens it once the query is
  non-empty — not on focus. Structure, for the phase that builds it: absolutely
  positioned `top: calc(100% + 8px)`, left/right flush to the field, `z-index: 70`,
  white, 1px `#E2E8F0`, 14px radius, `0 24px 60px rgba(15,23,42,.18)`. Rows are 52px
  min-height, `8px 14px`, `border-top #F1F5F9`, each a 30px brand-tinted icon tile, a
  14px/600 truncating title over a 12px muted meta line, and a right-aligned 12px/700
  `.07em` uppercase kind label — `Ticket` (≤5), `Person` (≤3), `Invoice` (≤3). Empty
  state is centred 14px muted: `Nothing matches "<term>".` Below lg the design moves the
  whole thing into an `mSearchBar` strip under the header with a 44px field and an
  inline (non-floating) panel. **Reported, not built.**
- **The account menu's three destinations.** Profile settings, Keyboard shortcuts and Sign
  out are wired and focusable but open nothing — each is marked `// TODO: dialog later`.
  The design routes the first two into dialogs and the third into the login screen; none
  of those exists yet.
- **The sidebar footer.** Still inert — it is not a second account trigger.
- **Org switcher.** The chevron in the sidebar header is an affordance only — it opens
  nothing.
- **Role-gated nav** (B6) and **every screen**. `/` is a placeholder heading and no other
  in-shell route exists yet, so the active-nav state is covered by
  `test/features/shell/nav.test.ts` rather than by a screenshot.
